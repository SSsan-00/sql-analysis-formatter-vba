# SQL Analysis Formatter 利用ガイド

T-SQLの識別子を和名へ変換し、Excel上にSQL解析結果と定義表を作成するツールです。

## 動作環境

- 64ビット版Windows
- VBAマクロを利用できるデスクトップ版Excel
- `SqlAnalysisFormatter.Parser.exe`を実行できる環境

parserは.NET 8の実行環境を内包した単一EXEです。通常は.NETを別途インストールする必要はありません。

## 受け取るファイル

配布方法によって、次のどちらかを受け取ります。

| 配布方法 | 使用するファイル |
| --- | --- |
| セットアップ済みブック | `SqlAnalysisFormatter.xlsm`、`SqlAnalysisFormatter.Parser.exe` |
| 既存ブックへ導入 | `SqlAnalysisFormatter.bas`、`SqlAnalysisFormatter.Parser.exe`、`README.md` |

## 最短で使う

`SqlAnalysisFormatter.xlsm`を受け取った場合は、この方法が最短です。

1. 作業用フォルダを作成します。
2. `SqlAnalysisFormatter.xlsm`と`SqlAnalysisFormatter.Parser.exe`を同じフォルダへ置きます。
3. ダウンロードしたファイルがWindowsにブロックされている場合は、各ファイルの`プロパティ`を開き、`許可する`（ブロックの解除）を選択します。項目が表示されなければ、この操作は不要です。
4. `SqlAnalysisFormatter.xlsm`をExcelで開きます。
5. セキュリティ警告が表示された場合は、配布元を確認したうえでマクロを有効化します。
6. 和名へ変換する場合は`変換定義`シートへ定義を入力し、`SQL解析`シートで`解析`ボタンを押します。変換が不要なら空のまま解析できます。

推奨する配置は次のとおりです。

```text
SqlAnalysisFormatter/
|-- SqlAnalysisFormatter.xlsm
`-- SqlAnalysisFormatter.Parser.exe
```

会社のセキュリティポリシーでマクロやEXEが禁止されている場合は、設定を回避せず管理者へ確認してください。

## 初回セットアップ

既存のExcelブックへ`.bas`を導入する場合の手順です。

1. 対象ブックのバックアップを作成します。
2. 対象ブックをExcelで開き、`Excelマクロ有効ブック (*.xlsm)`として保存します。
3. `Alt + F11`でVBAエディターを開きます。
4. `ファイル` -> `ファイルのインポート`を選択します。
5. `SqlAnalysisFormatter.bas`を選択して取り込みます。
6. VBAエディターを閉じ、Excelで`Alt + F8`を押します。
7. マクロ一覧から`SetupWorkbook`を選び、`実行`を押します。
8. `変換定義`、`SQL解析`、`アウトプット①`、`アウトプット②`、`テーブル一覧`の5シートと、`解析`、`クリア`、各アウトプットの`コピー`ボタンが作成されたことを確認します。
9. ブックを保存します。
10. 保存したブックと同じフォルダへ`SqlAnalysisFormatter.Parser.exe`を置きます。

利用者がインポートするのは`SqlAnalysisFormatter.bas`だけです。`SqlAnalysisFormatterTests.bas`は開発者用なので取り込みません。

### Bootstrapから展開する場合

配布元からユーザー向けBootstrapを受け取った場合は、PowerShellで次のように実行します。実行中にGitHubへの通信は行いません。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\SqlAnalysisFormatter.user.bootstrap.ps1 -TargetDirectory C:\Tools\SqlAnalysisFormatter
```

展開先には`SqlAnalysisFormatter.bas`、`SqlAnalysisFormatter.Parser.exe`、`README.md`が作成されます。展開後は上記の「初回セットアップ」に進みます。

## 使い方

### 1. 必要に応じて変換定義を入力する

和名へ変換する場合は、`変換定義`シートの2行目以降へ入力します。変換定義が空の場合も解析を実行でき、SQL解析シートと`アウトプット①`には物理名を保持して表示します。対応済みの物理テーブルで参照テーブルの和名を取得できない場合は、`(和名未取得)[users]`のように物理テーブルIDを併記します。

| A: 所属テーブルID | B: 所属テーブル和名 | C: フィールドID | D: フィールド和名 |
| --- | --- | --- | --- |
| users | ユーザー | user_id | ユーザーID |
| users | ユーザー | name | 氏名 |
| - |  | status | 状態 |

- `users.user_id`は`users.ユーザーID`へ変換します。テーブルID自体は変換しません。
- A列が`-`の場合、`status`のような単独フィールドも`状態`へ変換します。
- A列が`-`の単独フィールドについて、`アウトプット①`の解析で所属するSQL別名が一意に決まった場合は、SQL解析シートのC列以降にある対応する変換内容にも`tb1.状態`のように同じプレフィックスを付けます。B列の変換後SQLは従来どおり入力表記を保ちます。C列以降はプレフィックス補完をメモリ上で統合して最後に一度だけ書き込み、同じ最終値を重複表示しません。
- 参照する実テーブルが1つだけで、A列`-`のB列に有効なテーブル和名が1種類だけある場合、参照テーブルは`ユーザー`のように和名だけを表示します。SQLに明示別名があれば`ユーザー[u]`のように表示します。B列の和名が複数種類ある場合は推測しません。
- B列のテーブル和名は、`アウトプット①`の参照テーブル表示に使用します。
- `#temp_users`のような一時テーブルは、A列へ`#`を含む名前を入力します。SQLで別名を付けても、`アウトプット①`の参照テーブル和名を物理名から解決します。物理名が定義と一致しない場合は、参照テーブルを`(和名未取得)[#temp_users]`、列を元の物理名で表示します。
- D列が空欄または`(和名未取得)`の定義は変換しません。
- 変換定義シートのA～D列では、値が`(和名未取得)`のセルを`#FCE4D6`で塗りつぶします。それ以外の値へ変更すると塗りつぶしはなくなり、再び`(和名未取得)`へ変更すると自動的に色が付きます。
- `AS`直後の単独IDは列エイリアスとして扱い、SQL解析シートのB列では変換しません。`アウトプット①`では、式が参照する列のフィールドIDとエイリアスが一致する場合、そのフィールド和名を取得項目名に使用します。
- D列には`[]`、`/`、空白、括弧、演算子、引用符、コメント記号なども入力できます。SQL構文と区別して解析し、B列と`アウトプット①`には入力した和名をそのまま表示します。
- `=`、`+`、`-`、`@`で始まる和名は、Excelの数式判定を避けるため`'=合計`のように先頭へアポストロフィを付けて入力します。解析結果にはアポストロフィを含めず、`=合計`と表示します。

### 2. SQLを貼り付ける

1. A5:SQL Mk-2（A5M2）でT-SQLを開きます。
2. `Ctrl + Q`で整形します。
3. 整形結果全体をコピーします。
4. `SQL解析`シートのA2セルを選択し、通常どおり貼り付けます。

改行されたSQLは、A2、A3、A4のように1行ずつ別セルへ貼り付けられます。SQL全体をA2の1セルへ押し込む必要はありません。A列2行目以降の空白でない行を、1つのクエリとして解析します。

貼り付け後は、例えば次のように並びます。

| セル | 内容 |
| --- | --- |
| A2 | `SELECT` |
| A3 | `    users.user_id,` |
| A4 | `    users.name` |
| A5 | `FROM users` |

解析後はB3が`users.ユーザーID,`、B4が`users.氏名`となり、変換内容は同じ行のC列以降へ表示されます。

### 3. 解析する

`SQL解析`シートの`解析`ボタンを押します。

| 確認場所 | 出力内容 |
| --- | --- |
| SQL解析 B列 | 行ごとの和名変換後SQL |
| SQL解析 C列以降 | その行で変換された内容を1セルずつ表示 |
| アウトプット① | AST解析から作成した定義表 |
| アウトプット② | SQLへデータを供給するテーブルと書き込むテーブルの一覧 |

## アウトプット①

| SQL | 出力形式 |
| --- | --- |
| SELECT | `＜DB入出力項目定義＞` |
| サブクエリ、WITH | `サブクエリ[名前]` |
| SELECT INTO | 実在する`サブクエリ[名前]`、`＜DB入出力項目定義＞`、`＜データ移送表＞` |
| INSERT VALUES | `＜データ移送表＞` |
| INSERT SELECT | 実在する`サブクエリ[名前]`、`＜DB入出力項目定義＞`、`＜データ移送表＞` |
| SELECTを含まないDELETE、UPDATE | `＜データ移送表＞` |
| SELECTを含むDELETE、UPDATE | 内側の`サブクエリ[名前]`、`＜データ移送表＞` |

- SELECT INTOとINSERT SELECTのトップレベルSELECTは人工的なサブクエリへ分けず、`＜DB入出力項目定義＞`へ出力します。各取得式はデータ移送表の同じ位置にある対象項目へ直接対応させます。
- SELECT INTO、INSERT、UPDATE、DELETEのデータ移送表では、参照テーブルを移送先、移送元の順に`、`区切りで表示します（例: `(和名未取得)[#wkuser]、ユーザー[tb1]`）。移送元テーブルを持たない通常のINSERT VALUESは移送先だけを表示し、値式にスカラーサブクエリがあれば移送先、`SQn`の順に表示します。
- SELECT INTOとINSERT SELECT内に実在するサブクエリ、CTE、派生テーブルは、トップレベルSELECTより先に`サブクエリ[名前]`として出力します。
- 更新系SQLにSELECT処理が含まれる場合は、SELECTの解析表を先、最終的なデータ移送表を後に出力します。
- UPDATEの検索条件に`EXISTS`、`IN (SELECT ...)`、比較用サブクエリがある場合も、SELECTを`サブクエリ[SQn]`へ分け、データ移送表の検索条件からSQ名で参照します。
- INSERT VALUESの値式にスカラーサブクエリがある場合も、SELECTを`サブクエリ[SQn]`へ分け、データ移送表の移送元からSQ名で参照します。
- FROM句がないUPDATEでも、更新対象テーブルをデータ移送表の参照テーブルへ表示します。
- WITH句は名前付きサブクエリとして扱います。
- ネストしたサブクエリは内側から外側、最後にクエリ全体の順で出力します。
- 無名サブクエリには`SQ1`、`SQ2`の名前を付けます。
- 未対応のSQLは、SQL解析シートのB列と同じ和名変換後SQLをA列へ1行ずつ出力します。
- フォールバック時は1行空けた末尾へ`フォールバック原因`と、原因クエリがある`アウトプット①`の行範囲を表示します。
- 解析完了時にも警告ダイアログへフォールバック理由を表示します。parserが原因の論理行を特定できた場合は、その論理行に対応する`SQL解析`シートのA列セルを選択して表示します。1つのセルに複数行のSQLがある場合は、そのSQLを保持するセルを選択します。parser未配置など原因行がない場合はセルを移動しません。
- 解析結果へ表示するSQL断片は、タブ、改行、連続空白などの不可視空白を半角スペース1個へ統一します。文字列リテラル、角括弧識別子、二重引用符識別子の内部にある空白は原文どおり保持します。未引用の関数名は大文字へ統一しますが、`dbo.[CURRENT_TIMESTAMP]()`のような引用されたユーザー定義関数名は括弧と文字種を含めて原文どおり表示します。
- JOINの`＜＞`内には、各ON条件が実際に参照するJOIN対象テーブルを表示します。連鎖JOINで以前に登場したテーブルを参照する場合もそのテーブルを選び、同じ側の複数テーブルを参照する場合は`、`区切りで列挙します。未修飾列などから参照先を特定できない場合は、JOIN構造上で隣接するテーブルを表示します。ON条件はWHERE/HAVINGと同じ配置規則を使い、括弧、`AND`、`OR`、`NOT`を条件の階層に応じて複数行へ展開し、元SQLの評価順序を維持します。
- SELECTの取得項目にある`tb1.*`は`tb1.全項目`、修飾のない`*`は`全項目`として表示します。SELECT INTOではデータ移送表の対象を`全項目`、移送元を`tb1.全項目`として対応させます。
- SELECT取得式の未修飾列は、FROM句と変換定義から所属テーブルが1つに決まる場合だけSQL上の別名を補います。たとえば`name`が`tb1`だけに定義されていれば、取得項目とデータ移送表の移送元へ`tb1.name`と表示します。A列が`-`の定義も、同じB列を持つA列付きの別定義を介してFROM句内の1つの別名だけに対応する場合は、その別名を補います。D列に和名があれば`tb1.名前`、空欄なら`tb1.name`と表示します。同じB列に対応する別名が複数ある場合や、A列付きの対応定義がない場合は推測で修飾しません。
- `TRIM(tb1.name) AS name`のように式エイリアスが参照列のフィールドIDと一致する場合は、定義済みのフィールド和名を取得項目名へ表示し、式本体を`※`に続けて表示します。CASE式ではWHEN条件を除外し、ネストを含むすべてのTHEN・ELSE末端が単一列由来で、物理列名と和名がともに同じ場合だけ、同じ物理列名のエイリアスを和名化します。TRIMやCASTで包まれた単一列も対象です。ELSEなし、定数結果、複数列結果、物理列名または和名の不一致、異なるエイリアスでは元のエイリアスを表示します。
- 更新系では、単純なテーブル列参照だけを`移送元`へ出力します。SUMなどの集計、関数、算術演算、CASTなどの式は`移送方法ほか`へ出力し、式が参照するテーブル列を出現順・重複なしの`、`区切りで`移送元`へ併記します。COUNT(*)、変数、定数など特定のテーブル列を参照しない式では`移送元`を空欄にします。
- SELECT INTO、INSERT SELECT、UPDATE SET、INSERT VALUESのCASEは、`CASE結果`と分岐を`移送方法ほか`へ出力します。CASEがCAST、関数、演算、括弧など任意の外側式で包まれていても、`CAST(CASE結果 AS ...)`のように外側式を保って展開します。外側式とTHEN/ELSEの戻り値が参照するテーブル列は、出現順かつ重複なしで`tb1.name、tb1.age`のように`移送元`へ列挙します。WHEN条件だけが参照する列は含めず、対象となる列参照がなければ`移送元`は空欄にします。
- INSERT SELECTのトップレベルSELECTにある計算式はデータ移送表の移送元または移送方法へ直接対応させ、JOIN、検索条件、グループ、集計条件は`＜DB入出力項目定義＞`へ出力します。INSERT対象列を省略した場合は、SELECT取得項目のエイリアス、単純列の末尾名、または式の原文を取得順の仮移送先として扱います。変換定義に一致する項目名は移送先テーブルの和名へ解決し、`*`と`tb1.*`はそれぞれ`全項目`と`tb1.全項目`として表示します。これはSELECT取得順に挿入するという解析上の表示であり、実テーブルの物理列順との一致は検証しません。
- INSERT SELECTのトップレベルにUNIONまたはUNION ALLがある場合、SELECT側では`＜UNION＞`または`＜UNION ALL＞`を表示し、データ移送表側では各SELECTを`＜移送パターン1＞`、`＜移送パターン2＞`のように分けてINSERT対象列へ対応させます。集合演算のタグはデータ移送表側へ重複表示しません。INSERT対象列を省略した場合は第1SELECTの取得項目から仮移送先を決め、各分岐の取得項目数が一致しなければフォールバックします。
- INSERT VALUESは対象列を明示した単一行と複数行に対応します。複数行では`＜VALUES n行目＞`のラベルに続けて行ごとのデータ移送表を出力します。CASEは前項の配置規則に従い、同一項目の複数行を1つの枠で囲みます。DEFAULT VALUESとINSERT EXECUTEは原因付きでフォールバックします。
- CASEはSELECT項目、集計関数、WHERE、HAVING、GROUP BY、ORDER BY、JOIN、TOP、OFFSET、UPDATE SET、INSERT VALUES内で複数行へ展開します。列エイリアスのないSELECT項目は`CASE結果`として表示し、ELSE分岐は原文どおり`ELSE`と表示します。外側の式・関数を`※`の右側へ表示する場合、単一CASEの分岐は外側式の開始位置から8列右へ下げます。1式に複数のCASEがある場合は、番号付きの`CASE結果n`を外側式から14列下げ、各分岐を`CASE結果n`から6列下げます。複合WHEN条件はCASE直下の先頭条件を基準列に置き、AND/ORに続く条件と異なる論理グループを2列ずつ右へ下げます。元SQLの括弧は省略せず、各グループの先頭条件へ開き括弧、末尾条件へ閉じ括弧を表示します。THENまたはELSEの直下にCASEがある場合は、親条件と内側の先頭条件を同じ行へ直接連結し、内側の残りの分岐を2列右へ表示します。
- 罫線は取得項目、条件、結合、移送項目などの表本体だけを外枠で囲みます。タイトル行と参照テーブル行は外枠に含めません。
- データ移送表で移送方法へ置くCASEが複数行へ展開される場合は、行間罫線を付けず、その項目の行全体を1つの枠で囲みます。

### SELECT INTOの項目を和名にする

`AS display_name`のような式エイリアスは、次の変換定義で`アウトプット①`用の和名を指定できます。

| A: 所属テーブルID | B: 所属テーブル和名 | C: フィールドID | D: フィールド和名 |
| --- | --- | --- | --- |
| `-` | 空欄可 | `display_name` | `表示名` |

SQL内の`AS display_name`自体は変更しません。`＜DB入出力項目定義＞`と`＜データ移送表＞`では`表示名`として出力します。

`アウトプット①`はA列からCL列を使い、MSゴシック9ポイント、列幅1.14、行高13.5、目盛り線なし、折り返しと縮小表示なしで整形します。

## テーブル一覧とアウトプット②

`テーブル一覧`は、解析をまたいで保持する物理テーブルのマスターです。1行目はヘッダーで、2行目以降へ次の3項目を入力します。

| A: テーブルID | B: テーブル名称 | C: 番号 |
| --- | --- | --- |
| users | ユーザー | 1-1 |

- テーブルIDには`users`のように、スキーマ名とSQL別名を除いた物理テーブル名を入力します。`[users]`と`users`、大文字と小文字は同じIDとして照合します。
- 番号は`1-2`のような`数値-数値`形式で入力します。
- 空行は無視します。テーブルIDが重複した場合は1回の警告を表示して解析を続け、最初に登録された行を使用します。
- SQL内の物理テーブルがマスターにない場合、そのテーブルは`アウトプット②`へ出力しません。

`アウトプット②`は左右2ブロックで、入力情報をA1から、出力情報をBA1から表示します。入力情報はSELECTや更新対象とは別のデータソースとして参照する実テーブル、出力情報はSELECT INTO・INSERT・UPDATE・DELETEと`OUTPUT ... INTO`の書込先です。INSERT VALUESは入力情報なしとして扱います。UPDATE/DELETEでは、対象自身の列をSET・WHERE・ONで参照しても、対象行セットを束縛するFROM/JOINに記述しても入力にはしません。別テーブルのJOIN、サブクエリ、CTE、派生テーブル、自己結合の別出現は入力とし、更新対象と同じ物理テーブルを独立したソースとして参照した場合は両ブロックへ表示します。CTE名、派生テーブルの別名、`SQ1`などは一覧へ出力せず、その内部で参照する実テーブルを対象にします。

`アウトプット①`の参照テーブル行にある`(和名未取得)[テーブルID]`は、そのIDが`アウトプット②`へ実際に表示する入力・出力情報のテーブルIDと完全一致した場合だけ、対応するテーブル名称へ補完します。たとえば`(和名未取得)[users]`と`users / ユーザー`が一致すれば、角括弧付きIDを残さず`ユーザー`と表示します。比較では前後空白、外側の角括弧、大文字小文字を既存規則で正規化します。SELECT INTOやINSERTの移送先も、和名未取得時は物理IDを保持するため同じ照合対象になります。変換定義で取得済みの名称、物理IDと一致しない`(和名未取得)[tb1]`、空欄または未取得の名称は補完しません。

各ブロックはNo、テーブルID、テーブル名称、番号で構成します。parser内部ではSQL内の初出順を保って重複を除き、`テーブル一覧`との照合後、番号の前半・後半を数値として昇順に並べて4行目から表示します。同じ番号のテーブルはSQL内の初出順を維持します。Noは並べ替え後、入力・出力でそれぞれ1から採番し、Noの2列だけを結合して中央揃えにします。ほかの項目は結合せず左揃えです。ヘッダーには`アウトプット①`と同じ背景色を使いますが、太字にはしません。各項目には外枠と行罫線を表示します。

複数ステートメントに未対応SQLが混在する場合は、アウトプット形式へ変換できたステートメントからだけ入力・出力テーブルを抽出します。未対応ステートメント内のテーブルは出力しません。対応できるステートメントが1件もない場合、SQL全体を構文解析できない場合、またはparserを利用できない場合は、`アウトプット②`をタイトルとヘッダーだけにします。`アウトプット①`のフォールバック表示は従来どおりです。

### 成果物をコピーする

`アウトプット①`または`アウトプット②`の`コピー`ボタンを押すと、それぞれの使用範囲をExcelのクリップボードへ登録します。貼り付け先では通常の`Ctrl + V`を使用します。

## クリアするときの注意

`クリア`ボタンを押すと確認ダイアログを表示します。承認すると、次の内容をクリアします。

- `変換定義`シートの2行目以降
- `SQL解析`シートの2行目以降
- `アウトプット①`シートの内容と出力書式
- `アウトプット②`シートの内容と出力書式

`テーブル一覧`の登録内容はクリアしません。1行目のヘッダーが変更されていても復元します。変換定義も削除されるため、再利用する定義は事前に別ファイルへ保管してください。
クリア後も操作中のシートは切り替わりません。5シートすべてで、選択セルとスクロール位置がA1へ戻ります。

## バージョンを更新する

1. 対象ブックのバックアップを作成します。
2. `Alt + F11`でVBAエディターを開きます。
3. `標準モジュール`にある既存の`SqlAnalysisFormatter`を右クリックし、`SqlAnalysisFormatterの解放`を選びます。
4. エクスポート確認では、別途バックアップ済みなら`いいえ`を選択します。
5. 新しい`SqlAnalysisFormatter.bas`をインポートします。
6. `SetupWorkbook`を実行し、ブックを保存します。
7. `SqlAnalysisFormatter.Parser.exe`も新しいファイルへ置き換えます。

既存の入力データはモジュールの更新だけでは削除されません。
`.bas`とparser exeは連携形式が対応する同じ配布版へ一緒に更新してください。

## 困ったとき

| 症状 | 確認すること |
| --- | --- |
| シートやボタンがない | `Alt + F8`から`SetupWorkbook`を実行します。 |
| マクロを実行できない | ファイルのブロック解除、Excelのマクロ警告、組織のセキュリティポリシーを確認します。 |
| B列が空のまま | `変換定義`のA列、C列、D列と、`SQL解析`のA2以降を確認します。 |
| フィールドが変換されない | テーブル修飾付きならA列とC列、単独フィールドならA列が`-`か確認します。 |
| 列エイリアスが変換されない | `AS`直後は意図的に変換対象外です。 |
| `アウトプット①`にSQLがそのまま出る | 末尾の`フォールバック原因`を確認します。parser未配置ならEXE名、配置場所、Windowsのブロック状態を確認します。未対応構文なら原因を添えて開発者へ連絡します。 |
| 参照テーブルが`(和名未取得)[テーブルID]`になる | 対象テーブルIDに対応する変換定義B列、または`テーブル一覧`のテーブル名称を確認します。 |

parserが見つからない場合や実行に失敗した場合も、B列とC列以降の和名変換は継続します。この場合、`アウトプット①`は分解せず、和名変換後SQLをA列へ1行ずつ表示して末尾へ原因を表示し、`アウトプット②`はタイトルとヘッダーだけを表示します。

## セキュリティと通信

- parserの解析処理はPC内で完結します。
- 利用時にGitHubへ通信しません。
- 一時ファイルはWindowsの一時フォルダへ作成し、処理後に削除します。
- 配布元が確認できないマクロやEXEは実行しないでください。
